# N7 Construction — сайт

Статический сайт компании N7 Construction (строительство, развитие, инфраструктура, Казахстан и СНГ).
Исходники получены от партнёров архивом `n7-site.zip`, распакованы в корень; сам архив из этой ветки удалён как дубликат (оригинал остался в `main`).
Дополнительно прислан прайс-лист `price list-N7.pdf` (Hebei Enlio Sports Goods) — на его основе сделан раздел «Продукция».

## Запуск локально

Сайт полностью статический, сборка не нужна:

```bash
python3 tools/serve.py
```

Открыть `http://localhost:3000/`. Важно открывать именно через HTTP: при `file://` часть скриптов и шрифтов работает некорректно.

`tools/serve.py` — тот же статический сервер, но он не отдаёт `_source/`, `tools/`, `.git/`, исходный архив и служебные `.md`/`.py`: служебные материалы не должны попадать в публичный доступ. Обычный `python3 -m http.server` для превью использовать не стоит — он отдаёт все файлы подряд.

## Заявки → Telegram (безопасно)

Статический GitHub Pages **не может хранить токен бота**: любой JS виден посетителю.
Поэтому секрет живёт только в Cloudflare Worker, а сайт знает лишь публичный URL.
Полная инструкция — `tools/telegram-proxy/README.md`; кратко:

1. Токен, который был прислан в чате, надо отозвать у `@BotFather` и выпустить новый:
   он светился в открытом виде.
2. `cd tools/telegram-proxy && npx wrangler deploy`, секреты — `npx wrangler secret put
   TELEGRAM_TOKEN` и (необязательно) `TELEGRAM_CHAT_ID`. Если chat id не задан, воркер
   возьмёт последний чат из `getUpdates` — достаточно написать боту один раз.
3. Полученный `https://…workers.dev` задать как `window.N7_LEAD_ENDPOINT` либо
   `data-endpoint` у `<form id="lead">`. Это **публичный** URL, его можно коммитить.

Что куда уходит:

| Источник | Путь |
|---|---|
| Форма `kontakty.html` (имя, телефон, направление, комментарий, лист подбора) | `POST` JSON → воркер → `sendMessage` |
| Результат квиза, калькулятор, лист подбора / КП | `n7Send()` → тот же воркер, `kind: quick`, без контактов |
| Если воркер недоступен | автоматический fallback на WhatsApp `wa.me/77778848818` + текст для копирования |

Воркер: CORS только для `https://q984q.github.io`, honeypot-поля, лимиты длины,
валидация телефона, HTML-экранирование, пометка «без контактных данных» для быстрых заявок.
Ни токен, ни chat id в репозитории не хранятся. Тесты без сети:
`npm test` в `tools/telegram-proxy` (форма, быстрые заявки, мок Bot API) (мок Bot API,
CORS, XSS, ошибки, `getUpdates`).

## Как теперь работает форма заявки

`main.js` поддерживает два режима:

1. **`N7_LEAD_ENDPOINT` задан** — форма отправляет `POST` с JSON на защищённый прокси,
   валидирует имя, телефон и согласие, очищает поля и показывает «Заявка отправлена».
2. **Endpoint не задан** — без сервера: браузер собирает текст заявки, открывает WhatsApp
   с готовым сообщением и показывает кнопки «Отправить в WhatsApp», «Скопировать текст»,
   «Позвонить» плюс сам текст. Ссылки `kontakty.html?p=<артикул>` подставляют артикул
   в комментарий.

Точные цены, реквизиты и e-mail в репозиторий не добавляются.

## Каталог: анимации и освещение (`catalog-fx.js`)

Подключён на `produktsiya.html`, `sportivnye-pokrytiya.html`, `proekty.html`, `index.html`.

**Анимации (всё на `transform` / `opacity`, без библиотек):**
- **FLIP** при переключении фильтра: уцелевшие карточки «переезжают» на новые места, новые появляются каскадом. Позиции снимаются в capture-фазе до того, как `main.js` скрывает карточки.
- **Скользящий индикатор** активного фильтра (пересчитывается на `resize` и после загрузки шрифтов).
- **Световой блик**: радиальная подсветка фото следует за курсором, по карточке пробегает световой sweep.
- **Живой счётчик** «Показано N позиций из 13» с `aria-live`; ambient-подсветка фона секций.
- Полная деградация при `prefers-reduced-motion` и на устройствах без `Element.animate`.

**Освещение (`#osveshhenie` в `produktsiya.html`):** 8 типов светильников с анимированным включением световых лучей, переключатель «Включить/Выключить свет», фильтр с FLIP, таблица ориентиров освещённости по EN 12193:2018 (классы I–III) и предварительный расчёт: объект, класс, площадь, высота, мощность → число светильников, световой поток, установленная мощность, исполнение. Результат уходит в WhatsApp, цен не публикуем.

Расчёт — оценка методом светового потока (КИ 0,45–0,55, КЭ 0,8, 130 лм/Вт), **не** заменяет DIALux/Relux и проект. Для объектов в Казахстане уровни, GR, Ra и вертикальную освещённость при ТВ-съёмке подтверждают проектом по действующим нормам и требованиям федерации.

## Дизайн-система: скругления и тени

Единые токены заданы в `:root` и переопределены для тёмной темы в `style.css`, поэтому

| Токен | Значение | Где используется |
| --- | --- | --- |
| `--r-xs` / `--r-sm` / `--r-md` | 6 / 10 / 14 px | чекбоксы, копирование, бейджи, поля, панели, кнопки-иконки |
| `--r-lg` | 20 px | карточки каталога, направления, освещение, таблицы, карта, лайтбокс |

| `--sh-in` | внутренний блик по верхней кромке | кнопки, поля, карточки |

Дополнительно: карточки получили `overflow:hidden` (фото обрезается по радиусу),

кнопка «Наверх» стала кругом; `::selection` — в фирменном жёлтом.
Все эффекты уважают `prefers-reduced-motion`.


## Новый пакет: конверсия, поиск, квиз и ревизия интерфейса

Реализовано без внешних библиотек, сервисов и публикации цен. Все модули — ванильный JS
с `defer`, все состояния доступны с клавиатуры, `prefers-reduced-motion` и
`prefers-contrast` уважаются.

**Конверсия без бэкенда**
- **Лист подбора** (`n7-list.js`): соберите покрытие, корт, свет и результат квиза в один
  запрос КП. `localStorage`, счётчик в шапке, ссылка `?cfg=` (UTF-8 base64url),
  печать спецификации через `window.print()` и отдельный print-CSS, отправка в WhatsApp.
- **Поиск** (`n7-search.js`): ⌘K / Ctrl+K / `/`, 100 записей локального индекса
  (страницы, разделы, инструменты), `?q=`, на 404 открывается сам и подставляет путь в запрос.
- **Мастер заявки** (`n7-wizard.js`): 3 шага (объект → контакты → отправка), черновик
  в `localStorage`, валидация на каждом шаге и кнопка «Заполнить обычной формой».
  Логика отправки и WhatsApp-fallback остаются в `main.js`.
- **Квиз** (`n7-quiz.js`, `sportivnye-pokrytiya.html#quiz`): 6 шагов, мультивыбор приоритетов,
  две рекомендации, класс освещения, площадь, кнопки «в WhatsApp», «в лист подбора»,
  «пройти заново». Рекомендация помечена как предварительная.
- **Сравнение** 2–3 покрытий рядом, **димер** яркости III / II / I, синхронизированный
  с классом в расчёте освещения, и **Before/After**-ползунок (затемнение той же
  иллюстрации корта, честно подписанное как иллюстрация, а не фото объекта).

**Скорость и SEO**
- Self-hosted шрифты вместо Google Fonts, preload основного WOFF2 и LCP-изображения.
- 18 уникальных OG-превью (`tools/make_og.py`), `BreadcrumbList` на всех страницах с
  крошками, `FAQPage` на `sotrudnichestvo.html` и `kak-vybrat.html`, `WebSite` +
  `SearchAction` на главной, skip-link, `twitter:image`, `prefers-contrast`,
  `decoding="async"`, `sitemap.xml` с `lastmod`, `robots.txt` со служебными `Disallow`.
- **Bento-сетка** услуг на главной, **sticky-TOC** с прогрессом разделов на длинных страницах.

**Карта и база знаний**
- `n7-map.js`: SVG-карта Казахстана и СНГ с кликабельными странами, подсказкой и
  переходом в форму заявки. Карта справочная и прямо оговаривает, что не означает
  наличие офиса/склада/объектов в каждой стране.
- `kak-vybrat.html`: 6 шагов подбора, чек-лист вводных для КП, FAQ-аккордеон, ссылки
  на каталог, калькулятор и освещение. Страница добавлена в меню футера и sitemap.
- `o-kompanii.html#sec-3`: блок «Факты — только подтверждённые» — заглушки под кейсы
  с метриками, отзывы/логотипы, сертификаты и гарантии. Никаких выдуманных цифр.

**PWA-манифест**: `manifest.json` даёт иконку, цвета и установку ярлыка.
**Service worker отключён**: офлайн-SW перехватывал все навигации и мог вернуть
заглушку вместо страницы или закрепить старый `style.css` после деплоя. Файл `n7-sw.js`
оставлен как «самоудалитель» — он снимает регистрацию и чистит кэш у тех, кто успел
его установить; новые визиты SW не регистрируют.

**Версионирование ассетов.** Все локальные `style.css`, `fonts.css` и `*.js`
подключены с `?v=<метка>`. GitHub Pages кэширует статику, поэтому без этого браузер
может взять свежий HTML вместе со старым CSS — тогда новые блоки (квиз, лист подбора,
мастер заявки) показываются без оформления и кажется, что «весь интерфейс слетел».
После КАЖДОГО деплоя запускайте:

```bash
python3 tools/bump_assets.py <новая_метка>
```

и коммитьте изменённые HTML вместе с кодом. Посетителям всё равно полезен Ctrl+F5
при первом открытии после обновления.

## Навигация

В шапке 9 пунктов меню (включая «Освещение»), 4 иконки (тема, поиск ⌘K, лист подбора, бургер) и CTA
«Получить расчёт». Все вместе они не влезают в базовый контейнер `--w` (1200 px),
поэтому в `style.css` зафиксировано:

- `header .w` шире базового (`min(1520px, 100% - 40px)`);
- `nav a`, `header .btn`, `.logo` — `white-space:nowrap`, `nav ul` — `flex-wrap:nowrap`,
  `.tools` и логотип не сжимаются (`flex:0 0 auto`): пункты больше не переносятся
  («О компании» не превращается в «0 / компании»);
- горизонтальное меню показывается только на экранах **> 1600 px** с запасом по ширине,
  на всех ноутбуках и мобильных включается аккуратное выпадающее меню (бургер);
- на ≤ 640 px CTA скрыта, иконки уменьшены до 40 px — шапка влезает в 320 px;
- выпадающее меню ограничено по высоте и прокручивается.

Пункт «Подобрать за 60 сек» находится **в hero и в плавающей кнопке**, а не в `<nav>`:
в меню ровно 8 ссылок, по одной на `<li>`, на всех 18 страницах.

## Панель управления (все 18 страниц)

Единая панель `.toc.n7panel` создаётся в `n7-ui.js` на каждой странице: заголовок
«Управление» со счётчиком разделов, список разделов с подсветкой текущего
(`IntersectionObserver`), полоса прогресса прокрутки и один и тот же набор быстрых
действий — **Подобрать за 60 сек / Поиск по сайту / Лист подбора / Получить расчёт**.
На страницах, где меньше трёх разделов, вместо пустого оглавления показывается
навигация по сайту (10 пунктов) — внешне панель одинакова везде.

На ПК ≥1311 px панель раскрыта справа; на 761–1310 px сворачивается в узкую полоску
иконок, чтобы не перекрывать контент; на ≤760 px скрыта, её роль выполняет нижний
островок `dock`. Плавающая `.qfab` удалена — она дублировала кнопку квиза.

Правило бургера намеренно ограничено селектором `#menu`: раньше `nav{position:absolute;
inset:64px 0 auto}` применялось и к `nav.dock` / `nav.toc`, из-за чего на телефоне
открывался огромный белый блок, а панель исчезала на ноутбуке. Замер в headless
Chromium показал, что 9 пунктов меню + 5 кнопок влезают уже на 1401 px, поэтому
порог бургера снижен с 1600 до 1400 px.

В `screens/` лежат реальные скриншоты headless Chromium 153 (1440×900 и 390×844)
и сводный лист `overview.png`.

## Мобильная версия (≤ 760 px)

Вместо прилипшей к низу плашки «Позвонить / WhatsApp / КП» — плавающий
**«островок» навигации** (`#n7Dock`, создаётся в `features.js`): скруглённая пилюля
с отступами от краёв, размытием фона, тенью и учётом `env(safe-area-inset-bottom)`.
Пять вкладок — **Главная / Покрытия / ✦ Квиз / Поиск / Контакты**; центральная
жёлтая приподнята, активная подсвечена (`aria-current="page"`), «Поиск» открывает ⌘K.
На странице презентации Dock не показывается, чтобы не мешать слайдам.

**Горизонтально только короткие управляющие элементы**, где лента естественна:
фильтры каталога и освещения, чипы видов спорта, кнопки инструментов, шаги
мастера, хлебные крошки, hero-кнопки и панель сравнения. Выпадающее меню бургера —
**вертикальные блоки в 2 ряда** (9 пунктов, последний на всю ширину), а не лента.
Скроллбары скрыты глобально у всех контейнеров и на мобильном у `html/body`, `overscroll-behavior` не даёт ленте перелистывать
страницу, `prefers-reduced-motion` отключает анимацию появления.

**Контент оставлен вертикальным.** Карточки направлений, услуги на главной, 8 типов
освещения и этапы работ сначала были превращены в карусели, но на реальных
скриншотах 390×844 они выглядели обрубками («Прс…», половина второй карточки) —
вернули обычную сетку в одну колонку, всё читается целиком. Жёлтая кнопка «Наверх»
на телефоне скрыта: она перекрывала текст и дублировала dock. Под островок добавлен
отступ `body.has-dock`, выше него подняты тосты и панель сравнения.

## Презентация на телефоне

Слайды больше не центрируются в переполненном контейнере (`align-content:start`),

слайдов стали двухколоночными, картинки ограничены по высоте, снизу добавлен

← → · счётчик · иконка скачивания PDF; «На весь экран» и «Печать» на телефоне
скрыты. На первом слайде появляется подсказка «Свайпните или нажмите → чтобы
листать» и исчезает после первого переключения. Свайп и стрелки клавиатуры

## Если интерфейс «слетел» после обновления

1. **Ctrl+F5** (Windows) / **⌘+Shift+R** (Mac) — принудительно перезагрузить CSS и JS.
2. Убедитесь, что в исходниках у `style.css`, `fonts.css` и скриптов стоит **актуальная**
   метка `?v=` (см. `tools/bump_assets.py`). Свежий HTML + старый CSS = неоформленные
   новые панели, квиз и мастер заявки.
3. Проверьте, что старый service worker снят: `n7-sw.js` теперь только удаляет
   регистрацию и чистит `n7-offline-*`. В DevTools → Application → Service Workers
   можно нажать **Unregister** вручную.
